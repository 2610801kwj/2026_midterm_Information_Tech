인공지능과 머신러닝

1-1. 규칙은 누가 만드는가?

컴퓨터가 문제를 해결하는 방법은 크게 전통적인 프로그래밍과 머신러닝으로 나눠 생각할 수 있다.

전통적인 프로그래밍

사람이 규칙을 직접 만든다. 

규칙 + 데이터
      ↓
    컴퓨터
      ↓
     결과

머신러닝

데이터와 정답을 이용하여 컴퓨터가 규칙을 찾아낸다. 

데이터 + 정답
      ↓
    컴퓨터
      ↓
   규칙 발견
★ 시험 핵심
전통적 프로그래밍: 사람이 규칙을 만든다.
머신러닝: 컴퓨터가 데이터에서 규칙을 찾는다.

1-2. 전통적인 프로그래밍과 머신러닝 비교

구분 전통적인 프로그래밍 머신러닝
규칙 사람이 작성 컴퓨터가 학습
입력 규칙 + 데이터 데이터 + 정답
핵심 명시적인 규칙 데이터에서 패턴 발견
새로운 데이터 작성된 규칙에 따라 처리 학습한 규칙으로 예측

1-3. 머신러닝의 기본 과정 

많은 데이터 준비
       ↓
정답이 있는 데이터 제공
       ↓
컴퓨터가 패턴 학습
       ↓
규칙 또는 모델 생성
       ↓
새로운 데이터 입력
       ↓
결과 예측
암기
데이터 + 정답 → 학습 → 규칙 발견 → 새로운 데이터 예측

1-4. 하나의 특징만으로 판단하면 생기는 문제

예를 들어 "귀가 뾰족하면 고양이다" 라는 규칙을 생각해 보자.

스코티시 폴드는 고양이지만 귀가 접혀 있다.

저먼 셰퍼드는 개지만 귀가 뾰족할 수 있다.

따라서 하나의 특징만 가지고 모든 대상을 정확하게 분류하기는 어렵다.

1-5. 퍼셉트론

퍼셉트론(Perceptron)은 인공 신경망을 구성하는 기본적인 단위이다. 

입력
 ↓
퍼셉트론
 ↓
출력

퍼셉트론을 여러 개 연결하면 인공 신경망을 만들 수 있다.

1-6. 인공 신경망의 구조 

입력층
  ↓
은닉층
  ↓
출력층

은닉층은 하나만 존재할 수도 있고 여러 개가 존재할 수도 있다.

입력층 → 데이터를 입력받는 층

은닉층 → 입력 데이터를 처리하고 특징을 학습하는 층

출력층 → 최종 결과를 출력하는 층

1-7. 신경망 그림 해석

신경망 그림에서 점 하나는 퍼셉트론을 의미하고, 선은 퍼셉트론 사이의 연결을 의미한다. 

● ─── ● ─── ●
│ ╲   │   ╱ │
● ─── ● ─── ●
│ ╱   │   ╲ │
● ─── ● ─── ●

실제 인공지능 모델에서는 매우 많은 퍼셉트론과 연결이 사용될 수 있다.

1-8. 깊은 신경망

은닉층을 여러 개 사용하여 깊게 구성한 신경망을 깊은 신경망이라고 한다.

영어로 Deep Neural Network라고 한다.

1-9. 딥러닝

깊은 신경망을 이용하여 학습하는 방법을 딥러닝(Deep Learning)이라고 한다.

헷갈림 주의
깊은 신경망 = 구조
딥러닝 = 학습 방법

1-10. CNN

CNN은 Convolutional Neural Network의 약자이다.

이미지처럼 공간적인 구조를 가진 데이터를 처리하는 데 효과적인 신경망이다.

왜 필요한가?

컴퓨터가 이미지를 단순히 픽셀 하나하나의 값으로만 비교하면 문제가 생긴다.

같은 사과라도 위치가 조금 달라지면 많은 픽셀의 값이 달라질 수 있다.

CNN은 이미지의 지역적인 특징 을 효과적으로 학습한다.

예: 선, 모서리, 무늬, 부분적인 형태 등

네트워크

5-1. 네트워크란?

여러 컴퓨터나 장치를 연결하여 데이터를 주고받을 수 있도록 만든 시스템이다.

5-2. LAN

LAN은 Local Area Network의 약자이다.

비교적 좁은 범위의 네트워크를 의미한다.

예: 학교, 집, 사무실 등

5-3. 네트워크 장치

장치 역할
스위치 네트워크 내부의 장치들을 연결
라우터 서로 다른 네트워크 사이에서 데이터를 전달
공유기 일반적으로 여러 장치를 네트워크에 연결하고 인터넷 접속을 공유
모뎀 통신망과 사용자 측 네트워크를 연결
라우터 → 네트워크와 네트워크 사이의 경로를 연결
스위치 → 같은 네트워크 안의 장치를 연결

5-4. IP 주소

네트워크에서 장치를 식별하기 위해 IP 주소를 사용할 수 있다.

IPv4 주소는 32비트로 구성된다.

일반적으로 8비트씩 네 부분으로 나누어 십진수로 표현한다. 

192.168.0.10

각각의 숫자는 0부터 255까지 표현할 수 있다.

5-5. IPv4

IPv4는 32비트 주소 체계이다. 

8비트 + 8비트 + 8비트 + 8비트
      = 총 32비트

5-6. 도메인

사람이 IP 주소를 직접 외우는 대신 기억하기 쉬운 이름을 사용할 수 있다.

이러한 인터넷 주소 이름을 도메인 이름이라고 한다.

5-7. DNS

DNS는 Domain Name System이다.

도메인 이름을 IP 주소와 연결하여 인터넷 통신에 활용할 수 있도록 한다.

DNS 암기
사람이 이해하기 쉬운 도메인 이름 ↔ 컴퓨터 네트워크에서 사용하는 IP 주소

5-8. DHCP

DHCP는 네트워크에 연결된 장치가 IP 주소 등의 네트워크 설정을 자동으로 받을 수 있도록 해준다.

5-9. 게이트웨이

다른 네트워크로 나가기 위한 출입구 역할을 하는 장치를 게이트웨이라고 생각할 수 있다.

게이트웨이 = 다른 네트워크로 나가는 문
6

IP와 서브넷

6-1. 서브넷이란?

하나의 네트워크를 더 작은 네트워크 단위로 나누는 것을 서브네팅이라고 한다.

나누어진 각각의 작은 네트워크를 서브넷이라고 한다.

6-2. 서브넷 마스크

IP 주소에서 네트워크 부분과 호스트 부분을 구분하기 위해 사용하는 것이 서브넷 마스크이다. 

IP 주소
192.168.1.10

서브넷 마스크
255.255.255.0

6-3. 네트워크 부분과 호스트 부분

서브넷 마스크의 비트가 1인 부분은 네트워크 부분, 0인 부분은 호스트 부분으로 생각한다. 

IP
11000000.10101000.00000001.00001010

Mask
11111111.11111111.11111111.00000000

위에서는 앞의 24비트가 네트워크 부분이고 뒤의 8비트가 호스트 부분이다.

6-4. CIDR 표기

서브넷 마스크를 /숫자 형태로 간단하게 표현할 수 있다. 

255.255.255.0

↓

/24

/24는 앞에서부터 24비트가 네트워크 부분이라는 의미이다.

6-5. 자주 나오는 CIDR

CIDR 네트워크 비트 호스트 비트 대표적인 마스크
/8 8 24 255.0.0.0
/16 16 16 255.255.0.0
/24 24 8 255.255.255.0
/25 25 7 255.255.255.128
/26 26 6 255.255.255.192
/27 27 5 255.255.255.224
/28 28 4 255.255.255.240
/29 29 3 255.255.255.248
/30 30 2 255.255.255.252

6-6. 호스트 비트 계산

IPv4는 총 32비트이다.

따라서 

호스트 비트 = 32 - 네트워크 비트

예: 

/24

32 - 24
= 8

호스트 비트 = 8

6-7. 호스트 수

호스트 비트가 H개라면 이론적으로 만들 수 있는 주소 수는 

2^H

일반적인 IPv4 서브넷에서는 네트워크 주소와 브로드캐스트 주소를 호스트에게 할당하지 않으므로 

사용 가능한 호스트 수
= 2^H - 2

6-8. /24 예제 

/24

호스트 비트
= 32 - 24
= 8

전체 주소
= 2^8
= 256

일반적인 사용 가능 호스트
= 256 - 2
= 254
/24 → 8비트 호스트 → 256개 주소 → 일반적으로 254개 사용 가능

6-9. 네트워크 주소

호스트 부분을 모두 0으로 만든 주소를 네트워크 주소라고 한다.

예를 들어 192.168.1.25/24라면 

192.168.1.0

이 네트워크의 네트워크 주소가 된다.

6-10. 브로드캐스트 주소

호스트 부분을 모두 1로 만든 주소를 브로드캐스트 주소라고 한다.

192.168.1.25/24의 경우 

192.168.1.255

가 브로드캐스트 주소가 된다.

6-11. /24에서 기억할 것

/24 네트워크 24비트
호스트 8비트
네트워크 주소 마지막 부분 0
브로드캐스트 마지막 부분 255
전체 주소 256개
사용 가능 일반적으로 254개

6-12. 같은 네트워크인지 판단하기

두 IP가 같은 서브넷에 속하는지 확인하려면 네트워크 부분이 같은지 확인한다.

예: 

192.168.1.10/24
192.168.1.200/24

둘 다 네트워크 부분이 192.168.1로 같다.

따라서 같은 네트워크에 속한다. 

192.168.1.10/24
192.168.2.10/24

네트워크 부분이 다르므로 같은 /24 네트워크가 아니다.

7-1. 2진수의 자리값 

128 64 32 16 8 4 2 1

각각은 2의 거듭제곱이다. 

2^7 2^6 2^5 2^4 2^3 2^2 2^1 2^0

128  64  32  16   8   4   2   1

예를 들어 13을 생각하자. 

8 + 4 + 1
= 13

따라서 

00001101

이 된다.

7-3. 2진수 → 10진수 

00001101

0×128
+ 0×64
+ 0×32
+ 0×16
+ 1×8
+ 1×4
+ 0×2
+ 1×1

= 13

7-4. 255 

11111111

모든 비트가 1이면 

128+64+32+16+8+4+2+1
= 255
IPv4 한 옥텟의 최댓값은 255이다.

7-5. 서브넷 마스크와 2진수 

255.255.255.0

11111111.11111111.11111111.00000000

1이 24개이므로 /24이다.

  • 버블 정렬
  • 선택 정렬
  • 병합 정렬

이 포함된다.

8-1. 버블 정렬

인접한 두 데이터를 비교하여 순서가 잘못되어 있으면 교환한다.

한 번의 반복이 끝날 때마다 큰 값이 뒤쪽으로 이동하는 모습을 생각하면 쉽다. 

5 2 4 1

5와 2 비교
→ 교환

2 5 4 1

5와 4 비교
→ 교환

2 4 5 1

5와 1 비교
→ 교환

2 4 1 5
버블 정렬
핵심: 인접한 값끼리 비교하고 교환

8-2. 버블 정렬 특징

  • 서로 이웃한 데이터를 비교한다.
  • 필요하면 두 값을 교환한다.
  • 큰 값이 뒤쪽으로 이동한다.
  • 여러 번 반복하여 전체를 정렬한다.

8-3. 선택 정렬

선택 정렬은 아직 정렬되지 않은 부분에서 가장 작은 값을 선택하여 앞쪽으로 가져오는 방식이다. 

5 2 4 1

가장 작은 값 = 1

1 2 4 5

다음 구간에서
가장 작은 값 = 2

1 2 4 5
선택 정렬
"가장 작은 것을 골라서 앞으로"

8-4. 선택 정렬 특징

  • 정렬되지 않은 부분을 찾는다.
  • 그중 최솟값을 찾는다.
  • 앞쪽의 현재 위치와 교환한다.
  • 이를 반복한다.

8-5. 버블 vs 선택

구분 버블 정렬 선택 정렬
핵심 인접한 값 비교 최솟값 선택
주요 행동 비교 후 교환 최솟값을 찾아 교환
암기 옆끼리 비교 작은 것 선택

8-6. 병합 정렬

병합 정렬은 데이터를 작은 부분으로 나눈 다음 정렬하면서 다시 합치는 방식이다. 

5 2 4 1

      ↓

5 2     4 1

 ↓       ↓

5  2    4  1

      ↓

2 5     1 4

      ↓

1 2 4 5
병합 정렬
나눈다 → 각각 정렬한다 → 합친다

8-7. 병합 정렬의 핵심

병합 정렬에서 가장 중요한 단어는 분할과 병합이다. 

전체
 ↓
작게 분할
 ↓
정렬
 ↓
정렬된 부분들을 병합
 ↓
완성

8-8. 세 정렬 한 번에 비교

알고리즘 핵심 행동 암기 키워드
버블 인접한 값 비교·교환 옆끼리
선택 최솟값 선택 작은 것 선택
병합 분할 후 병합 나누고 합치기
9

탐색 알고리즘

9-1. 순차 탐색

순차 탐색은 데이터를 처음부터 하나씩 차례대로 확인하면서 원하는 값을 찾는 방법이다. 

데이터:

4 7 2 9 5

찾는 값: 9

4 → 아님
7 → 아님
2 → 아님
9 → 찾음
순차 탐색 = 처음부터 하나씩

9-2. 순차 탐색의 특징

  • 데이터를 처음부터 확인한다.
  • 각 데이터를 순서대로 비교한다.
  • 데이터가 정렬되어 있지 않아도 사용할 수 있다.

9-3. 이진 탐색

이진 탐색은 정렬된 데이터에서 매우 효율적으로 값을 찾는 방법이다.

가운데 값을 확인한 뒤 찾는 값이 어느 쪽에 있는지 판단하여 탐색 범위를 절반으로 줄인다. 

1 2 3 4 5 6 7 8 9

찾는 값 = 8

가운데 = 5

8은 5보다 큼
→ 오른쪽만 탐색

6 7 8 9

가운데 = 7

8은 7보다 큼
→ 오른쪽

8 9

가운데 = 8

→ 찾음
★ 이진 탐색의 필수 조건
데이터가 정렬되어 있어야 한다.

9-4. 순차 vs 이진

구분 순차 탐색 이진 탐색
방법 처음부터 하나씩 가운데부터 범위를 절반씩 줄임
정렬 필요 필요 없음 필요함
핵심 순서대로 확인 중간값 기준으로 범위 축소

9-5. 이진 탐색에서 가장 중요한 것 

정렬
 ↓
가운데 확인
 ↓
왼쪽 또는 오른쪽 선택
 ↓
범위 절반
 ↓
반복
이진 탐색 = 정렬 + 가운데 + 절반

데이터 압축

10-1. 데이터 압축이란?

데이터를 표현하는 데 필요한 저장 공간이나 전송량을 줄이는 기술이다.

압축의 핵심 목적:
데이터 크기를 줄인다.

10-2. 왜 압축하는가?

  • 저장 공간을 절약할 수 있다.
  • 데이터 전송량을 줄일 수 있다.
  • 전송 시간을 줄이는 데 도움이 된다.

10-3. 무손실 압축

압축한 뒤 다시 복원했을 때 원본 데이터를 완전히 복구할 수 있는 방식이다. 

원본
 ↓
압축
 ↓
복원
 ↓
원본과 동일

문서나 프로그램처럼 정보가 하나라도 달라지면 안 되는 데이터에 적합하다.

10-4. 손실 압축

일부 정보를 제거하여 데이터 크기를 크게 줄이는 방식이다. 

원본
 ↓
일부 정보 제거
 ↓
압축
 ↓
복원
 ↓
원본과 완전히 같지는 않을 수 있음

사람에게 큰 차이가 느껴지지 않는 정보 등을 줄이는 데 활용할 수 있다.

10-5. 무손실 vs 손실

구분 무손실 압축 손실 압축
원본 복원 가능 완전 복원 불가능할 수 있음
정보 손실 없음 있음
특징 원본 보존 크기를 크게 줄일 수 있음
압축 ≠ 암호화
압축은 데이터 크기를 줄이는 것이고,
암호화는 데이터를 보호하는 것이다.
11

데이터 암호화

11-1. 암호화란?

데이터를 허가되지 않은 사람이 쉽게 이해할 수 없도록 변환하는 기술이다. 

평문
 ↓
암호화
 ↓
암호문
 ↓
복호화
 ↓
평문

11-2. 평문

암호화하기 전의 원래 데이터를 평문이라고 한다.

11-3. 암호문

암호화된 데이터를 암호문이라고 한다.

11-4. 복호화

암호문을 다시 원래 데이터로 되돌리는 과정을 복호화라고 한다.

평문 → 암호화 → 암호문
암호문 → 복호화 → 평문

11-5. 암호화의 목적

  • 데이터의 기밀성을 보호한다.
  • 허가받지 않은 사람이 내용을 알아보기 어렵게 한다.
  • 통신 과정에서 정보를 보호하는 데 활용한다.

11-6. 암호화와 압축 비교

구분 압축 암호화
목적 크기 감소 정보 보호
핵심 효율적인 저장·전송 기밀성
결과 작아진 데이터 알아보기 어려운 데이터
