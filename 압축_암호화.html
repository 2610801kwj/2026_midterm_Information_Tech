1. 디지털 데이터

컴퓨터는 현실 세계의 정보를 그대로 이해하는 것이 아니라 정보를 디지털 데이터로 변환하여 처리한다.

핵심: 현실의 연속적인 정보를 컴퓨터가 처리할 수 있는 디지털 형태로 바꾸는 과정이 중요하다.

대표적인 대상은 사진, 소리, 영상, 문자 등이다.

2. 표본화

표본화(Sampling)는 연속적인 아날로그 신호를 일정한 시간 간격으로 측정하여 표본을 얻는 과정이다.

예시

마이크가 사람의 목소리를 받아들인다고 생각해 보자.

실제 소리는 시간에 따라 연속적으로 변하지만, 컴퓨터는 모든 순간의 값을 무한히 저장할 수 없다.

따라서 일정한 간격마다 소리의 크기를 측정한다.

표본화 = 시간축에서 얼마나 자주 측정하는가

표본화 주파수

1초 동안 몇 번 표본을 얻는지를 표본화 주파수라고 한다.

단위는 Hz를 사용한다.

예를 들어 44,100 Hz라면 1초에 44,100번 측정한다는 의미이다.

시험 포인트:
표본화 → 신호를 일정한 시간 간격으로 측정

3. 양자화

표본화한 값은 여전히 연속적인 값일 수 있다.

컴퓨터에서 저장하려면 이를 일정한 단계의 값으로 나누어 표현해야 한다.

이 과정을 양자화(Quantization)라고 한다.

양자화 = 측정한 값을 정해진 단계의 값으로 바꾸는 것

쉽게 구분

과정 무엇을 하는가?
표본화 언제 측정할 것인가?
양자화 측정한 값을 어떤 단계로 표현할 것인가?
부호화 그 값을 어떤 디지털 코드로 나타낼 것인가?
암기:
표본화 → 시간
양자화 → 값의 단계
부호화 → 코드

4. 부호화

양자화된 값을 컴퓨터가 처리할 수 있는 디지털 코드로 표현하는 것을 부호화(Encoding)라고 한다.

컴퓨터에서는 대표적으로 0과 1을 이용한다.

표본화 → 양자화 → 부호화

이 세 과정을 연결해서 기억하면 된다.

아날로그 신호 ↓ 표본화 ↓ 양자화 ↓ 부호화 ↓ 디지털 데이터

5. 손실 압축

손실 압축은 압축 과정에서 일부 데이터를 제거하여 파일 크기를 줄이는 방법이다.

압축을 풀어도 원본과 완전히 동일하지 않을 수 있다.

손실 압축
일부 정보 제거 → 파일 크기 감소 → 원본과 완전히 같지 않을 수 있음

대표적인 예

  • JPEG 이미지
  • MP3 음악
  • AAC 음악
시험에서 자주 묻는 것:
"압축 해제 후 원본과 완전히 동일한가?"

손실 압축 → 아니오

6. 무손실 압축

무손실 압축은 데이터를 압축하더라도 압축을 해제하면 원래 데이터를 완전히 복원할 수 있는 방법이다.

무손실 압축
정보를 정확하게 보존 → 압축 해제 시 원본 복원 가능

대표적인 예

  • PNG
  • GIF
  • FLAC

문서나 프로그램 파일처럼 데이터가 조금이라도 달라지면 문제가 되는 경우 무손실 압축이 중요하다.

7. 연속 길이 부호화(RLE)

연속 길이 부호화(RLE, Run-Length Encoding)는 같은 데이터가 연속해서 반복될 때 반복되는 데이터와 반복 횟수를 이용하여 짧게 표현하는 방법이다.

RLE 핵심:
연속해서 반복되는 데이터 → 데이터 + 반복 횟수

예시

원본: AAABBBBBBBCCCCC ↓ RLE 압축 A3B7C5

각각의 의미는 다음과 같다.

원본 압축 표현 의미
AAA A3 A가 3번 반복
BBBBBBB B7 B가 7번 반복
CCCCC C5 C가 5번 반복
중요:
AAABBBBBBBCCCCC → A3B7C5

이것은 사전 기반 압축이 아니라 RLE(연속 길이 부호화)이다.

주의할 점

연속길이 붛ㅗ화는 데이터가 연속적으로 많이 반복될 때 효과적이다. 반복되지 않는 데이터가 많으면 압축 효과가 작거나 오히려 표현이 길어질 수도 있다.

8. 사전 기반 압축

사전 기반 압축은 데이터에서 이미 등장한 문자열이나 패턴을 다시 저장하는 대신, 기존에 등장한 데이터를 참조하여 더 짧게 표현하는 방식이다.

대표적으로 LZ 계열 압축에서 이러한 원리가 사용된다.

핵심:
이미 나온 문자열을 다시 그대로 저장하지 않고
상대적 위치 + 길이 등의 정보로 참조한다.

예시

원본: ABABABCABCAB 압축 표현: AB(2,4)C(3,5)

여기에서 괄호 안의 값은 (상대적 위치, 길이)를 의미한다.

표현 의미
AB 처음 등장하는 데이터를 그대로 저장
(2,4) 이미 나온 데이터의 상대적 위치와 길이를 이용해 참조
C 새롭게 등장한 데이터
(3,5) 앞에서 등장한 데이터를 다시 참조
시험 암기:

사전 기반 압축
= 이미 나온 데이터를 다시 저장하지 않고
= 위치와 길이 등의 정보로 참조

RLE와 사전 기반 압축의 차이

구분 RLE 사전 기반 압축
핵심 연속 반복 횟수를 기록 이미 나온 문자열을 참조
대표 예시 AAABBBBBBBCCCCC → A3B7C5 ABABABCABCAB → AB(2,4)C(3,5)
핵심 정보 데이터 + 반복 횟수 상대적 위치 + 길이 등
헷갈리지 말 것!

A3B7C5 → RLE
(2,4), (3,5)처럼 이전 데이터를 참조 → 사전 기반 압축

9. 압축률

압축이 얼마나 잘 되었는지를 나타내는 값으로 압축률을 사용할 수 있다.

압축률 공식

압축률 = 원본 데이터의 크기 ÷ 압축된 데이터의 크기

압축률은 일반적으로 몇 배로 압축되었는지를 나타내는 방식으로 이해하면 된다.

예시 1

원본 데이터가 100KB이고 압축된 데이터가 25KB라면:

100KB ÷ 25KB = 4 → 압축률 = 4배

예시 2

원본 데이터가 200MB이고 압축된 데이터가 50MB라면:

200MB ÷ 50MB = 4 → 압축률 = 4배
시험 포인트:

원본 100KB → 압축 후 25KB
100 ÷ 25 = 4
압축률 = 4배
주의:
이 페이지에서 사용하는 압축률은 원본 크기 ÷ 압축된 크기이다. "압축 후 크기가 원본의 몇 %"인지 묻는 문제와 "몇 배 압축되었는지"를 묻는 문제는 구분해야 한다.

10. 이미지 파일 형식

이미지 파일 형식은 색상 표현 방법, 투명도 지원 여부, 압축 방식 등에 따라 특징이 달라진다.

형식 정식 명칭 압축 주요 특징
BMP Bitmap 무압축 압축하지 않은 이미지 파일 형식. 픽셀 처리 방식에 따라 2가지 흑백 색상부터 1,680만 색상(24비트), 256단계 투명도(8비트)까지 지원할 수 있다.
PNG Portable Network Graphics 무손실 무손실 압축을 사용하며 투명한 배경을 지원한다. 1,680만 색상(24비트)과 256단계 투명도(8비트)를 지원한다.
GIF Graphics Interchange Format 무손실 무손실 압축을 사용하며 움직이는 이미지에 자주 사용된다. 일반적으로 0~255, 즉 256색(8비트)을 사용한다.
JPEG Joint Photographic Experts Group 손실 손실 압축을 사용한다. 고품질 사진에 자주 사용되며 일반적으로 1,680만 색상을 지원한다.

BMP

BMP(Bitmap)는 압축하지 않은 이미지 파일 형식이다.

픽셀 처리 방식에 따라 2가지 흑백 색상부터 1,680만 색상(24비트)까지 지원할 수 있으며, 256단계 투명도(8비트)를 지원할 수 있다.

PNG

PNG(Portable Network Graphics)는 무손실 압축을 사용한다.

투명한 배경을 지원하며 1,680만 색상(24비트)과 256단계 투명도(8비트)를 지원한다.

GIF

GIF(Graphics Interchange Format)는 무손실 압축을 사용한다.

움직이는 이미지에 자주 사용되며, 일반적으로 256색(8비트)을 사용한다.

JPEG

JPEG(Joint Photographic Experts Group)는 손실 압축을 사용한다.

고품질 사진에 자주 사용되며 일반적으로 1,680만 색상을 지원한다.

이미지 파일 형식 암기

BMP → 무압축
PNG → 무손실 + 투명 배경
GIF → 무손실 + 256색 + 움직이는 이미지
JPEG → 손실 + 사진 + 1,680만 색상

11. 소리 파일 형식

형식 정식 명칭 압축 주요 특징
WAV Waveform Audio File Format 무압축 압축하지 않은 소리 파일 형식. 파일 크기가 크지만 원래 디지털 소리 정보를 모두 보존하며 소리 편집에 사용된다.
FLAC Free Lossless Audio Codec 무손실 무손실 압축. WAV 파일보다 용량을 줄이면서도 원래의 음질을 최대한 유지할 수 있다.
MP3 MPEG-1 Audio Layer III 손실 사람의 귀로 듣기 어려운 일부 소리 정보를 제거하여 파일 크기를 줄인다. 적절한 음질을 유지하면서 용량을 줄이는 데 적합하다.
AAC Advanced Audio Coding 손실 손실 압축을 사용하며, 같은 압축률에서는 일반적으로 MP3보다 더 좋은 음질을 제공한다.

WAV

WAV(Waveform Audio File Format)는 압축하지 않은 소리 파일 형식이다.

파일 크기가 크지만 원래 디지털 소리 정보를 모두 보존하며 소리 편집에 사용된다.

FLAC

FLAC(Free Lossless Audio Codec)은 무손실 압축을 사용한다.

WAV 파일보다 용량을 줄이면서도 원래 음질을 최대한 유지할 수 있다.

MP3

MP3(MPEG-1 Audio Layer III)는 손실 압축을 사용한다.

사람의 귀로 듣기 어려운 일부 소리 정보를 제거하여 파일 크기를 줄인다.

AAC

AAC(Advanced Audio Coding)는 손실 압축을 사용한다.

일반적으로 같은 압축률에서 MP3보다 더 좋은 음질을 제공한다.

소리 파일 형식 암기

WAV → 무압축 + 크기 큼 + 소리 편집
FLAC → 무손실
MP3 → 손실 + 듣기 어려운 정보 제거
AAC → 손실 + 같은 압축률에서 일반적으로 MP3보다 음질 우수

12. 암호화

암호화는 데이터를 다른 사람이 쉽게 이해하지 못하도록 특정한 규칙에 따라 변환하는 것이다.

원래 데이터를 평문, 암호화된 데이터를 암호문이라고 한다.

평문 ↓ 암호화 ↓ 암호문 ↓ 복호화 ↓ 평문

암호화와 압축의 차이

구분 목적
압축 데이터 크기를 줄임
암호화 데이터를 보호함
압축했다고 해서 보안이 되는 것은 아니다. 암호화했다고 해서 반드시 파일 크기가 작아지는 것도 아니다.

13. 치환형 암호

치환형 암호는 문자의 위치는 유지하면서 문자 자체를 다른 문자로 바꾸는 방식이다.

예시

알파벳을 다음과 같이 바꾼다고 해보자.

A → D B → E C → F D → G ...

그렇다면

ABC ↓ DEF

가 된다.

치환형 = 글자를 다른 글자로 바꾼다.

중요한 특징

  • 문자의 위치는 기본적으로 유지된다.
  • 문자를 다른 문자로 바꾼다.
  • 대표적인 예로 시저 암호를 생각할 수 있다.

14. 전치형 암호

전치형 암호는 문자를 다른 문자로 바꾸는 것이 아니라 문자의 위치를 바꾸는 방식이다.

예시

원문: ABCDE 전치: CADBE

문자 자체는 그대로 A, B, C, D, E이지만 순서가 바뀌었다.

전치형 = 글자는 그대로, 위치를 바꾼다.

치환형과 비교

구분 치환형 전치형
문자 자체 바뀜 그대로
위치 기본적으로 유지 바뀜
핵심 문자를 다른 문자로 교체 문자의 순서를 변경
초간단 암기:

치환 = 다른 문자로 바꿈
전치 = 자리만 바꿈

시험 직전 30초 암기

표본화 = 시간 간격으로 측정
양자화 = 값의 단계를 정함
부호화 = 디지털 코드로 표현

손실 = 일부 정보 제거
무손실 = 원본 복원 가능

RLE = 연속 반복 + 반복 횟수
A3B7C5 = RLE

사전 기반 = 이미 나온 문자열을 참조
(상대적 위치, 길이) = 사전 기반 압축

압축률 = 원본 크기 ÷ 압축된 크기
100KB ÷ 25KB = 4배

BMP = 무압축
PNG = 무손실 + 투명 배경
GIF = 무손실 + 256색 + 움직이는 이미지
JPEG = 손실 + 사진

WAV = 무압축
FLAC = 무손실
MP3 = 손실
AAC = 손실 + 같은 압축률에서 일반적으로 MP3보다 음질 우수

치환 = 문자를 바꿈
전치 = 자리를 바꿈
기존 정보 시험범위로 돌아가기
